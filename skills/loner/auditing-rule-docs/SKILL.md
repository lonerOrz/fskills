# 规则文档体检与修复

两阶段执行。阶段一产出诊断报告，不改文件。阶段二仅在用户逐条确认后修复并验证。缺少确认动作时，禁止进入阶段二。

## 一、扫描范围

扫描范围为以下路径谓词命中的文本文件。未命中任一模式的路径不在扫描范围内，无需额外声明。

| 模式                    | 说明                 |
| ----------------------- | -------------------- |
| `AGENTS.md`             | 根目录及任意嵌套目录 |
| `CLAUDE.md`             | 根目录及任意嵌套目录 |
| `.claude/rules/**/*.md` | Claude Code 规则目录 |
| `skills/*/SKILL.md`     | 技能入口             |

### 覆盖清单（阶段一报告开头，必输出）

逐行格式：`路径 | 已扫描 / 不在扫描范围 | 依据（命中的模式，或“未命中任何模式”）`。行数必须等于上述模式命中的候选文件总数。遗漏任一候选即扫描不完整。

## 二、判定条件

一条记录计入某类问题，当且仅当满足该类全部计入条件，且不满足任何排除条件。仅满足部分条件时不计入，可在卡片备注写明接近条件。

### A 废弃历史叙事

| 计入（全满足）                                          | 排除（任一满足即不计入）                         |
| ------------------------------------------------------- | ------------------------------------------------ |
| ① 指称具体已弃用工具 / 已删除路径 / 已废止方案 / 旧版本 | 仅标注参考资料版本或日期                         |
| ② 给出“失败原因”“不再采用”或“已被替代”的描述            | 仅声明“以当前主线为准”，无失败原因               |
| ③ 该描述不用于说明当前规则的约束来源或迁移边界          | 迁移说明只列范围、退出条件或兼容期限，无失败叙事 |

改写：保留当前有效约束，删除失败原因，指称替换为“目标以 X 为准”或“参考资料只提取当前有效原则”。

### B 纯负向约束

| 计入（全满足）                                                                   | 排除（任一满足即不计入）                 |
| -------------------------------------------------------------------------------- | ---------------------------------------- |
| ① 条目以否定词开头或由否定词主导（不要 / 严禁 / 避免 / 禁止 / 不得 / 不可 / 勿） | 否定词后紧跟正向替代动作                 |
| ② 同段无对应正向动作、白名单、替代方案或完成判据                                 | 否定用于安全边界，且同段另有正向操作说明 |
| ③ 相邻段落也无对该否定条目的正向补充                                             | 否定排除明确反例，并给出反例的正面版本   |

改写：保留否定意图，在同段补上“应当做什么”“应当产出什么”或“如何判定完成”。改写后段落必须同时含否定意图与正向执行动作。

### C 机械格式脚手架

| 计入（任一满足）                                           | 排除（任一满足即不计入）                     |
| ---------------------------------------------------------- | -------------------------------------------- |
| ① 强制固定字段顺序或句式，且不服务于跨条目可比性或机器解析 | 表格或卡片用于跨条目横向比较                 |
| ② 强制固定叙事框架，要求内容适配框架而非按内容类型组织     | 固定字段用于机器解析、审计留痕或下游工具消费 |
| ③ 强制固定输出模板，但字段与本次信息类型不匹配             | 模板允许按内容调整或增删字段                 |

改写：保留可比性或机器解析要求，固定套话改为“必须覆盖以下信息，可用表格或分段按内容自然组织”。

## 三、阶段一输出：卡片报告

同一段落或相邻三行内的同类问题合并为一张卡片，原句列全部行号。卡片字段全部必填：

| 字段        | 内容                                           |
| ----------- | ---------------------------------------------- |
| 编号        | A1 / B1 / C1，按类型分组                       |
| 文件 + 行号 | 可定位；跨行写起止行                           |
| 原句        | 逐字引用，必须能在文件检索到，禁止改写缩写补全 |
| 危害        | 一句话：该写法如何影响模型注意力或执行质量     |
| 改写建议    | 可直接替换原文的正向版本，保留原意图           |
| 判定依据    | 满足的计入条件编号；边界案例写排除条件         |

### 优先级（报告末尾）

每条按三维度各 1–3 分，缺一不可：

| 维度       | 1          | 2          | 3                          |
| ---------- | ---------- | ---------- | -------------------------- |
| 影响范围   | 单条局部   | 一个章节   | 跨章节或多类任务           |
| 改写可行性 | 需重新设计 | 需重写一段 | 单句替换                   |
| 注意力风险 | 轻微干扰   | 可能误读   | 直接导致错误执行或空泛交付 |

总分 = 三项之和。取最高前 3 条为“优先处理”；并列时注意力风险高者优先，仍并列按文件路径字典序。

### 报告末尾必附

1. 汇总表：类型 / 卡片数 / 涉及文件数。
2. 优先处理前 3 条：编号 + 一句话理由 + 三维度得分。
3. 自检，逐项“通过 / 不通过”：覆盖清单行数 = 候选文件数；每卡行号可定位；每卡原句可逐字检索；汇总数 = 正文卡片数；优先条目均有三维度得分。

自检存在“不通过”时，禁止标记阶段一完成。

## 四、阶段二：修复与验证

启动条件：用户明确指定要修复的卡片编号，或授权“全部修复”。仅此两种形式。

### 修复规则

1. 只改被确认卡片对应的原文，未被确认的原文一律不改。
2. 每处修改使用卡片“改写建议”的正向版本，或语义等价表述。
3. 改写后原文仍须满足原条目意图；不得删除原条目想禁止的行为或想保留的约束。
4. 禁止顺带修改相邻段落、格式、无关条目或引入新规则。

### 验证（每张已修复卡片逐项检查）

| 检查项       | 通过标准                                 |
| ------------ | ---------------------------------------- |
| 原句已消失   | 旧原句在文件中检索不到                   |
| 新句可定位   | 改写后的句子能在文件中定位到行号         |
| 意图保留     | 新句仍表达原条目的否定或约束意图         |
| 判定不再命中 | 用阶段一计入条件复判该处，结果为“不计入” |
| 未波及       | diff 仅含被确认卡片对应的行              |

任一不通过，该卡片状态为“未完成”，不得标记“已修复”。

### 阶段二禁止

用户确认前禁止改文件；禁止修改未确认卡片；禁止“顺手优化”；验证未通过禁止标完成；禁止运行与文件内容无关的命令。

## 五、交付说明（阶段二结束）

逐卡列出：`编号 | 文件:行号 | 改写后原句 | 五项检查结果 | 状态（已修复 / 未完成）`。

末尾附：未修复卡片及原因、验证未通过项、本轮 diff 文件清单。存在“未完成”卡片时，禁止称本轮“全部完成”。
